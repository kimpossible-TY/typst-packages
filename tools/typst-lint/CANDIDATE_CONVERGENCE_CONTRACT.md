# Bounded in-memory candidate convergence

`candidate_convergence.py` composes the existing partial parser-backed rule
proposals. It does not use `edit_plan.Analysis.complete`, establish complete
rule coverage, acquire an editor lease, replace a consumer file, invoke a
compiler, install packages, or authorize a build gate. A successful candidate
remains a partial, non-applicable-transaction proposal.

## API and proof boundary

`converge(tree, initial_results, analyze_candidate, validate_step,
validate_final, *, movement_proofs=None, max_passes=8)` returns a frozen
`Candidate` only after all mandatory proof callbacks and independent zero-edit
reanalysis succeed.

- The baseline must be immutable UTF-8 and its supplied `Tree` must exactly
  equal a fresh parse of those bytes/mode. Arbitrary syntax recovery is absent.
- `initial_results` and each reanalysis are mappings from existing rule IDs to
  frozen rule results with tuple diagnostics, edits, skips, parse errors, and
  suppressed findings. The module retains read-only mapping snapshots.
- `analyze_candidate(Tree)` runs the actual supported rules with their original
  captured context. No synthetic complete flag, inferred semantic finding ID,
  fabricated resolver fact, or replacement-text search certifies ownership.
- `validate_step(before_tree, before_results, after_tree, after_results, step)`
  certifies each transition. The parent preserves available rule keys, rejects
  new analysis refusals, and verifies exact directive/suppressed-finding
  ownership. The module independently rejects changed rule keys and rule parse
  failures. Intermediate active findings may expose the next eligible repair.
- `validate_final(candidate)` verifies final active findings are a subset of
  the original findings with source-bound mapped positions, and preserves
  original suppressed owners. It must not treat an unchanged finding count or
  an equal-looking replacement string as identity evidence.
- The final candidate is reparsed and reanalyzed independently. Its complete
  result mapping must equal the retained final mapping, and its new edit plan
  must have neither applied nor deferred edits. This is deterministic partial
  analysis, not complete graph/build validation.

Both proof callbacks are mandatory. They remain parent-owned because rule
coverage, configuration ignores and compound marker suppression semantics
belong to the source-analysis adapter, not a generic byte composer.

## Captured context

Package sources, reference catalog, selected-source bytes, entrypoint snapshot,
and relative import graph remain immutable. The analyzer callback derives
candidate-only context from the exact original snapshot, without filesystem
rereads, import traversal, runtime Typst evaluation or expanded dependencies.
Only an entrypoint snapshot already matching the original path/bytes can be
rebased. Import-graph rebasing uses the existing bounded `rebase_graph` contract;
a stale graph is not rescued. Rule implementation/catalog code is unchanged.

## Passes and refusal

Each pass validates and deterministically coalesces identical proposals using
`edit_plan.plan`. Overlaps are deferred, never assigned an arbitrary winner.
If an independent edit makes progress, the candidate is reparsed and the rules
may reconsider the deferred region. If all remaining edits conflict, fail.
There are at most eight edit passes, plus final zero-edit and independent
idempotence checks. A caller may request a smaller bound, not a larger one.
Repeated source states, parse failure, changed rule availability, failed proof
callbacks, nonconvergence, unresolved conflicts and nondeterministic reanalysis
raise `SafetyError` before any applicable patch is returned.

## Baseline edits and attribution

Every `Step` retains exact before/after immutable bytes, applied and deferred
`AttributedEdit` records, and explicitly proved import moves. Each
`Contribution(pass_number, rule_id, edit)` retains the actual local-coordinate
rule proposal. No contributor is inferred from a diagnostic count.

Final `Candidate.edits` are a single nonconflicting plan in the original source
coordinates. Edits touching generated bytes expand to that prior replacement's
original baseline envelope. Conflict closure is required in both current and
baseline coordinates, including insertions touching an envelope boundary.
Unchanged prefixes/suffixes are replayed exactly; no diff algorithm discovers
correspondence. Every pass and final baseline plan must replay the exact bytes
that were parsed. No-op envelopes disappear from the prospective patch while
their causal steps remain retained.

Each final edit has a deterministic `primary_rule_id`, the first causal owner
in stable pass/edit/rule order, and a sorted `rule_ids` tuple containing every
contributing owner of that envelope. A multi-owner replacement is not emitted
as duplicate overlapping edits and is not silently attributed only to its
primary rule. Initial diagnostics remain separate from composition metadata;
a later-pass owner need not have had an initial diagnostic.

## Source-bound coordinates

`Step.map_offset` maps its own exact preimage's byte coordinate to its postimage.
`Candidate.map_offset` chains those maps from the original baseline. Insertions
have right affinity. Consumed bytes return `None`, even when the replacement
contains equal text. EOF maps as a boundary. A caller must not replace `None`
with an invented offset when matching unresolved or suppressed owners.

`map_boundary(position, side='left'|'right')` separately maps construct
endpoints with explicit insertion affinity. Exact outer replacement boundaries
can survive while interior boundaries return `None`. Directive proofs compare
rules, reason, mapped span, mapped directive start, actual target AST kind and
a surviving source-origin token. Function-call anchors use the actual callee
through parentheses; literal Text retains its last byte so the separately proven
first-byte capitalization remains possible. Entirely replaced same-kind calls
cannot inherit an old directive merely because their outer bounds match.

An import reorder cannot use an ordinary monotonic offset shift. The optional
`movement_proofs(before_tree, after_tree, applied_edits, before_results)`
callback supplies exact `(start, end, target)` tuples from root import AST spans.
The module independently checks adjacent Hash/ModuleImport shape, complete
statement bytes, unique source/target identity within one applied replacement,
nonoverlap, and ownership by that exact replacement. It never discovers moves
by searching arbitrary source or diagnostic strings. Unproven replacement
interiors remain consumed. The retained per-pass maps, not a final broad
baseline envelope, preserve original diagnostic owners inside moved imports.

## Evidence

`tests/test_candidate_convergence.py` uses the actual pinned parser and existing
rule analyzer for highlight extraction then standalone-display formatting,
standalone-display formatting then display-continuation gap repair, scripts,
configuration ignores, unresolved catalog findings, actual import reordering,
BOM/CRLF/Unicode/comments and source suppression. It verifies immutable captured
package/catalog/entrypoint/graph context and exact baseline/per-pass replay.
A merged-envelope fixture retains a real original import diagnostic's byte
owner through AST movement and a later separator insertion. That insertion is
a coordinate-composition fixture, not a claim of production rule eligibility.

Explicitly fault-injected analyses cover parser failures, changed rule keys,
rule parse failures, new refusals/findings, directive retargeting, conflicts,
repeated states, exactly eight passes, limit exhaustion and nondeterministic
zero-edit reanalysis. Deterministic pure byte-composition property fixtures
exercise repeated text, deletions, insertions, consumed/generated bytes and
cross-pass multi-owner envelopes. These tests do not manufacture semantic IDs
or establish eligibility for any additional repair.

The combined dispatcher explicitly opts into the existing casing policy's
exact eligible lowercase initial after marker insertion. The direct marker
backend remains unchanged by default; actual subsequent parsing and resolution
supply the separate one-byte repair. See PROSE_MARKER_CONTRACT.md and the real
marker-followup CLI/render tests. Generic convergence grants no new casing policy.


## Serialized evidence authentication

Multi-pass report records retain exact hashes, applied attributed edits and AST
movement tuples. These records do not authenticate themselves. The audit captures
an independent `AnalysisContext` while its isolated fixture still exists, checks
its input/config/catalog/package evidence against the actual CLI, and retains the
immutable resources after the fixture is removed. Candidate analysis never
rereads those resources or consults a package cache.

Every repaired file, including apparently single-pass proposals, requires that
independent context. `authenticate_candidate` recomputes real raw rules and the
complete bounded convergence, with step/final ownership checks and independent
zero-edit reanalysis. Reported final baseline edits, primary/contributing rule IDs
and pass counts must match that independently recomputed lineage. Multi-pass
records must exactly match its canonical history, with strict JSON primitive
types rather than Python's bool/int/float equality. Missing/wrong baseline hashes,
stripped history, false valid rule IDs, duplicate or repeated-state histories,
malformed attribution and missing contexts are blocked, not certified by a
fallback offset guess. The audit still separately compares final actual CLI
coverage, findings and read-only invariants; authentication is not complete rule
acceptance or a source-write permission.
